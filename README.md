# detective_engine —— 约束驱动的推理小说生成引擎（地基版）

[English](README_EN.md) | [简体中文](README.md)

把"侦探推理 = 证据串成链"这个想法落成一个**可运行、可扩展**的引擎骨架。

## 核心立场

纯随机组合痕迹不会产生"精妙"，只会产生噪音。因为：

- 痕迹的随机组合，绝大多数根本不是一个**可解的流程**（约束满足问题几乎全无解）；
- 精妙 = **惊异 × 必然 × 唯一**。随机擅长制造惊异，却造不出"读者回想觉得只能如此"的必然，也保证不了"只可能是一个解"。

所以本引擎的做法是**倒推**：

```
真相轨迹(Trajectory) --造成--> 痕迹(Trace) --挑选+排序--> 呈现(Plot) --打分--> Score
        随机只在这层选原料                     手艺在这层                       选择在这层
```

## 分层结构

| 文件 | 职责 |
| --- | --- |
| `detective/model.py` | 数据模型：`Trace` / `Trick` / `World` / `Trajectory` / `Plot` |
| `detective/trick_library.py` | **诡计库**：每个机关的成立前提、必然痕迹、揭晓方式 |
| `detective/element_library.py` | 原料库：核心真相线索、红鲱鱼、人物/地点池、世界设定 |
| `detective/constraints.py` | 约束：前提满足、诡计冲突、**公平性**、一致性 |
| `detective/scorer.py` | **评价函数**：必然 / 唯一 / 惊异 / 经济 / 一致 / 时机 / 多样；精妙 = 必然 × 唯一 × 惊异 |
| `detective/generator.py` | 倒推生成管线 + 骨架去重排序 |

## 运行

```bash
cd detective_engine
python demo.py                              # 生成并打印最精妙的候选
python -m unittest discover -s tests -v     # 自检
```

## 三条可扩展路线

1. **加诡计**：往 `trick_library.ALL_TRICKS` 追加 `Trick`，注明 `premises` / `traces` / `reveal`。生成器自动纳入。
2. **加世界**：往 `element_library.WORLDS` 加世界事实，即可开关不同诡计的组合空间。
3. **调口味**：改 `scorer.WEIGHTS` 与 `_INGENUITY_SHARE`，改变"什么算精妙"。

## 重构记录：从"越满越好"到"惊异 × 必然 × 唯一"

初版评分函数有个致命偏见：**惊异随红鲱鱼数量单调上升**，导致"最优解"永远是塞满 3 个诡计 + 3 条红鲱鱼的拥挤故事，且前几名是同模板克隆。

重构后：

- 精妙改为三项乘法 `必然 × 唯一 × 惊异`，缺一即崩；
- 惊异加入**边际递减 + 拥挤惩罚**（非单调）；
- 新增**唯一可解**（同一嫌疑人被多条红鲱鱼堆砌则扣分）；
- 新增**误导时机**（红鲱鱼前置、真相后置）与**反陈词滥调**（同类诡计不堆叠）；
- `rank` 增加**骨架去重**，不再输出克隆。

效果（郊区别墅 600 候选，前 50 名）：诡计数量不再出现 3，只留 1–2 个。

## 一个诚实的发现：任何固定评分函数都会诱导出自己的模板

重构修正了旧偏见，但**新偏见立刻浮现**。前 50 名的统计：

- 红鲱鱼几乎全是 3 条（惊异在上限内仍是单调的）；
- 凶手高度集中在"弟弟 / 司机 / 私人医生"——因为红鲱鱼指向的是"配偶 / 合伙人 / 前雇员 / 继承人"，评分函数于是**自动偏好那些没人怀疑的角色**（最不可能嫌疑人）。

也就是说：**你改的是"哪一套模板"，而不是"消灭模板"。** 这正是整个项目的核心结论——生成不难，难的是定义一个不会自我坍缩的"品味函数"。

## 已知边界（下一步可做）

- **唯一可解性仍是近似**：只按"嫌疑票数"判断替代解是否成立，没有真正做逻辑蕴含。
- **惊异 / 经济的标定**：红鲱鱼在可达范围内仍趋于饱和（3 条），需要更强或非线性的负载模型。
- **呈现顺序**只有"前置 / 打乱"两种，还没做真正的**信息节流曲线**。
- 时间线尚未建模为显式**事件图**。
- **诡计库仍太小**，这是新颖度的真实上限。

## 人机协作接口（重要）

诡计库与原料库是**人工输入优先**的。真实生活里的细节、你读推理小说时的灵感，都可以直接变成库里的元素：

- 一条现实观察 -> 一条 `Trace`（现象 + 表面误读 + 它真正指向什么）
- 一个"如果……会怎样" -> 一条 `Trick`（前提 + 必然痕迹 + 揭晓方式）

引擎负责组合、约束与打分；**灵感的质量由你定义**。这也正是把"品味"重新交回人手里的方式。
